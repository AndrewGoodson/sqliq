FINDINGS & EXPOSURE

Zero recorded findings does not establish that a database is secure. All 18 sample items remain unassessed.

What a finding must contain

Source section, affected endpoint or client, observed evidence, failed requirement and the reviewer’s applicability decision.

Financial relevance

Document the affected financial process and the potential confidentiality or service impact. Loss amounts, regulatory consequences and materiality need organization-specific evidence; none are estimated here.

Remediation record

Assign an owner, target date, proposed correction, validation steps and rollback plan. Execution requires a separate approval for the exact write plan.

ASSURANCE & CLOSURE

Before an item can pass

A reviewer must establish applicability and assess sufficient evidence for the requirement. A configured minimum TLS version alone cannot establish SP 800-52 conformance.

Board and audit review

Retain source references, evidence dates, scope, owner decisions and outstanding exceptions. Identify unassessed connections and separate Azure-inherited evidence from customer responsibilities.

After remediation

Collect fresh evidence under an approved read plan and record the review outcome. Keep “not applicable” decisions distinct from passes.

A SHARED PLATFORM. DISTINCT RESPONSIBILITIES.

What Azure provides

Managed endpoint and platform controls may be inherited when service-specific assurance supports them. Azure SQL, Managed Instance and SQL Server on VMs need different evidence.

What your team owns

Client drivers, certificate validation, trust stores and connection settings need customer evidence. A minimum TLS setting alone does not establish SP 800-52 conformance.

What the report establishes

A traceable review of supplied evidence. Banking and accounting obligations need organization-specific applicability decisions.

04 / GET STARTED

Start with the repository.
Keep production untouched.

Prepare the TLS review locally, then build an evidence register. The commands use no database credentials and do not scan a live endpoint.

Open setup instructions
LOCAL WORKSPACEPython 3.11+ / uv
# In your SQLIQ checkout
uv sync --locked --group dev
uv run azure-sql-agent verify
uv run azure-sql-agent graph

# Prepare a SQL TLS review
uv run azure-sql-agent guide \
  --workflow nist-tls

# Generate an offline evidence register
uv run azure-sql-agent compliance-report \
  --catalog nist-800-52 \
  --output tls-review.html

Guidance runs offline. Live reads and supported writes require external approval.
